## `.ioc` regeneration exception

The checked-in `firmware/dso138.ioc` records the STM32F103C8Tx, clocks, ADC1/ADC2, TIM2, ADC1 circular DMA, NVIC settings, selected button/LED pins and SWD. It does not describe the complete runtime project: notably it has no USB IP configuration, and it omits the source-owned LCD timer/DMA transport, direct-register USB driver and 1 KiB storage linker layout. `RCC.USBFreq_Value=48000000` is a recorded clock value, not USB peripheral configuration.

The build uses the hand-authored C++ `main` in `dso_platform_startup.cpp`, checked-in startup assembly, custom MSP setup and custom interrupt bindings. The `.ioc` currently has `ProjectManager.NoMain=false` and `ProjectManager.DeletePrevious=true`. Generated C entry/MSP/IRQ code could conflict with those owners or overwrite project integration. No clean regeneration-and-merge workflow has been demonstrated. **Use the existing CubeIDE project and treat `.ioc` as a partial hardware reference; do not regenerate it.** Auditing the reference does not certify CubeMX regeneration support.

## Hardware-dependent limits and deferred work

The R5 observations are bounded bench checks on the reference DSO138 PCB 109-13800-00C with STM32F103C8T6 and ILI9341. They do not establish production electrical compliance. The stock trial uses the board's fixed pull-up, assumes host VBUS and has no VBUS-sense or switched 3.0–3.6 V production pull-up. The USB ground is connected to PC ground; the interface is not isolated. Do not use it to make mains-referenced measurements safe. See the [USB hardware contract](usb-hardware.md).

Configured CPU/timer, ADC and USB clocks are 72 MHz, 12 MHz and 48 MHz respectively; configuration and timer metadata are not independent frequency measurements. The onboard test output shares the MCU timebase and cannot independently calibrate it. Calibration kind 1 is nominal, not measured calibration. Analog gain, zero, bandwidth, alias response and spectral amplitude accuracy remain instrument-specific and unqualified. Capture repetition, USB readout and display service have dead time; continuous streaming and gap-free capture are outside this release.

Real target work is deferred until this evening. The remaining target checks are FFT execution/display with unchanged raw samples, acquisition interference, a runtime stack watermark, and hardware-observable USB edge cases including the current MATLAB readiness guard. The offline tests above do not substitute for those measurements.
